# Working on dsx

dsx moves files between a Claude Design project and a local directory **without the bytes
passing through a model's context** — a pull that costs agents ~665k tokens costs dsx one
summary line. Every decision serves that; second to it, not losing data.

Read [PROTOCOL.md](PROTOCOL.md) before touching anything that talks to the server: the
endpoint is undocumented and parts of it are counter-intuitive enough that guessing produces
wrong code.

## Orientation

`main.go` holds only `func main` and `var version`. Everything else is a layer below, leaves
first; each imports only what is above it.

| Package | Holds |
|---|---|
| `internal/dsxerr` | error taxonomy and exit codes — the agent-facing contract. The one true leaf; imports nothing of ours |
| `internal/fmtutil` | `Truncate`, `Bytes`, and the two sanitisers — `Printable` for one field, `PrintableDoc` for a whole reply |
| `internal/reply` | one renderer per **measured** tool reply, each free to refuse. A leaf, because its decoders are simultaneously the live suite's protocol judges and the renderers' input — the only way the shape dsx draws and the shape PROTOCOL.md claims cannot drift |
| `internal/auth` | credential resolution. Reads the token, never writes or prints it (invariant 8). Keychain lane in `auth_darwin.go` |
| `internal/mcp` | JSON-RPC transport, retry, SSE unwrapping, error types; `read_file` window reassembly (`envelope.go`, `ReadFull`); the preview lane (`serve.go`, `ReadBinary`), the one place a `serve_url` exists |
| `internal/mcptest` | the fake endpoint. Never imports `mcp`, so `mcp`'s own tests can use it |
| `internal/syncer` | the sync engine. Data-loss-critical decisions stay unexported (`planPull`, `planPush`, `safeJoin`, `checkRemotePath`, `writeBatch`, `save`) |
| `internal/cmd` | command kernel: the `Command`/`Group`/`Needs` types and the shared parse/emit helpers. Knows nothing about which commands exist |
| `internal/cmd/<group>` | one package per product group (`conv`, `ds`, `escape`, `files`, `members`, `plans`, `projects`, `sync`), each exporting exactly one `Group`. A group carrying a `Noun` addresses as `dsx <noun> <verb>` (invariant 22); `cmdX` stay unexported |
| `internal/clitest` | the fake-endpoint adapter as a real package. `_test.go`-only, never in the binary |
| `internal/cli` | the program's view of itself: `Main`, `run`, the `groups` registry, generated `usage`, the `diag` group. Exports one name: `Main` |

Structure rules that are load-bearing, not taste:

- **`plan.go` is pure and has no import block.** Its decisions are testable without a network; keep it that way. `RemoteEntry`, `localFile`, `State`, `FileState` live beside it for the same reason.
- **`groups` (in `cli`) is the single source; `commandIndex`, `commandNames` and `usage` derive from it in `init()`.** `diag` stays in `cli` because `cmdHelp`/`cmdCompletion` read those derived vars and `groups` must sit above every group — a `diag` package would close an import cycle.
- **The sync engine is `internal/syncer`, and the sync command package is `synccmd` (dir `internal/cmd/sync`), never `sync`** — a package named `sync` beside `import "sync"` silently shadows the stdlib.
- **Group/command filenames carry no underscore.** Go reads the last `_`-segment as a build constraint, so `files_js.go` would build only under `GOOS=js`, silently.
- **The reference is checked against the server in three widths, and the narrowest two were added after the wide one missed things.** `TestTheRecordedToolsListNamesEveryToolDsxCallsByName` is offline and catches a truncated file. `missingFromReference` is live and catches a tool the server GREW — the direction nothing checked, which hid `list_comments`, `ack_comments` and `read_design_skill`. `schemaDrift` is live and goes one level below the name: both of this session's real defects lived inside a schema whose name never changed — `list_files` silently gained `depth` (a whole tree in one call, unused) and `render_preview` silently lost `render` (a dsx flag that went on being accepted, documented and inert). It compares argument names, the required set and `readOnlyHint`, and deliberately **not** descriptions: server prose churns, and a guard that fires on every rewording is one people switch off. Restoring the pre-change reference makes it name both defects verbatim, which is how it was verified. `--render` is gone from dsx as a result; `--validators` stays, because the server still declares it as "Reserved … Ignored today" — a slot it means to honour, not one it removed.
- **`WalkTree` asks for the whole tree in one call and distrusts the answer.** `list_files` gained `depth`, and `-1` returns every file with no directory stubs — 109 files in one request where the walk spends eleven. `walkFlat` reports `ok=false` for every departure from the measured shape and the proven recursive walk runs instead, because the two mistakes are not symmetric: a needless fallback costs one round trip, a flat listing wrongly believed costs the user's files, since every sync verb reads this map and `--prune` deletes what is absent from it. So no error is inspected and no listing is repaired — anything unexpected is simply not used. Five refusals are each pinned by a mutation, and the two that look like belt-and-braces are not. A listing that *reaches* the 20,000 cap is refused rather than one that exceeds it, because at the boundary a complete listing and a silently truncated one are identical bytes. And `null` is refused explicitly: it unmarshals into a nil slice **without an error**, so unguarded it reads as "this project has no files" and the next `push --prune` deletes every file on the server. The server was measured answering `[]` even for a path that does not exist, so `null` is a shape it never sends; the fakes were emitting it and now do not, which is what `listingFor`'s nil-fixup is for in both copies. The claim no fake can make — that flat and recursive describe the same tree — is checked live against real projects on path, size and etag.
- **A `serve_url` is born and dies inside `mcp.ReadBinary`, and exactly two hosts may be fetched.** `render_preview` returns a `*.claudeusercontent.com` URL carrying a token scoped to the whole PROJECT, valid ~1h, needing no `Authorization` header — so the string *is* an hour of read access to every file in the project. It is not a return value, not a report field and not an error argument: `ReadBinary` mints it, fetches it and drops it, which makes `grep serve_url` a complete audit. The bearer token is deliberately NOT sent with it (a second secret to a second host, for nothing), redirects are not followed — which turns out to matter for a second reason measured after the fact: an EXPIRED serve_url answers `302` to the `claude.ai/design` editor page, not `403` or `404`, so a client that followed redirects would hand an HTML page to whatever expected a PNG, and only the length check would stand between that and the user's disk — and the body is read through an `io.LimitReader` bounded by the size `list_files` reports — the exact-length check alone would catch an oversize body only after swallowing all of it, and a mutation removing the bound survived until a test measured how much the server managed to write. `allowServeHost` admits an https host ending in `.claudeusercontent.com` — matched on `Hostname()`, never on the string, or `attacker.test/.claudeusercontent.com/x` would pass — **or** the endpoint's own scheme/host/port. The second arm is not a loophole and is what makes the lane testable: that host already receives dsx's bearer token, so fetching bytes from it grants nothing new, and it means every fake endpoint serves its own preview lane with no test-only switch to widen by accident. Userinfo is refused on both arms (`https://x.claudeusercontent.com@evil.test/` is `evil.test`).
- **`internal/syncer/fake_test.go` is a deliberate duplicate of `clitest`** — syncer's internal tests can't import `clitest`, which imports `syncer` (a cycle).
- **A live test's judgment lives outside `//go:build live`; only its plumbing lives under it.** This is `plan.go`'s "pure, no import block" rule applied one layer up, and it was bought the same way. CI never compiles `live_test.go` — deliberately, its own comment says so, since it needs a real login and must not acquire one — so a mutation inside it fails nothing: of seven tried, six survived, including reverting a `t.Fatalf` to the `t.Logf` it had just replaced. Extracting the decision into an untagged `*Verdict` function with an ordinary table test moved fourteen such mutations from surviving everything to failing a bare `go test`. `etagVerdict`, `fetchBaselineVerdict`, `roundTripVerdict`. What cannot be recovered this way is whether the plumbing hands the judge the right values and calls the right endpoint; that residue is irreducible without the network, and it is the whole reason the live suite still exists. `livecheck_test.go` is the floor under the rest: it parses `live_test.go` as bytes — a build tag does not stop a parser — and fails a `TestLive*` that reaches no assertion at all. It cannot see one assertion weakened among several, and says so; do not read it as more than it is.
- **`flagSetOwners` reads a `NewFlagSet` name only when it is a string literal, and unions repeated assignments to one identifier.** Both halves were bought: an expression makes it fall back to attributing that FlagSet's flags to *every* command the package declares, which was harmlessly true while `synccmd` held only `pull`/`push`/`status` (they shared a set then; `status` no longer does — see invariant 19) and wrong the moment `clone` arrived; and assignment instead of union let a `switch` naming one literal per branch erase all but the last, leaving the earlier commands with no declarations and every `usageFooter` promise about them reading as a lie. Splitting `cmdSync` without the union measurably made things *worse* — ten failures where there had been none — so the union is the fix and the split *then* became possible. It has since happened, and `--force-with-lease` is what forced it: one FlagSet meant a push-only flag belonged to `pull` too, so documenting it made `dsx help` promise `pull` a flag the binary rejects, and a runtime refusal only hides that. `cmdPull` and `cmdPush` now declare their flags separately and the repetition is load-bearing — a shared helper taking `fs *flag.FlagSet` puts the name behind a parameter, and the reader falls straight back to attributing every flag to every command in the package. `TestFlagSetOwnersUnionsRepeatedAssignments` guards the reader. Widening a `usageFooter` scope to escape either is not a fix: the backward half reads the same set, so the test goes green and `dsx help` starts promising a flag the binary rejects.
- **The ledger's home is `.dsx/`, not the directory root.** `internal/syncer/state.go` holds `StateDir`/`StatePath`, `checkLedgerHome` and `ensureLedgerHome`; `internal/syncer/baseline.go` holds the fetch baseline (`.dsx/baseline.json`) and its own `loadBaseline`/`(Baseline).save`; `internal/syncer/fetch.go` is what fills it. `synccmd` gained `pin` (`internal/cmd/sync/pin.go`, backed by `internal/syncer/pin.go`), `unpin` (`internal/cmd/sync/unpin.go`, backed by `internal/syncer/unpin.go`) and `fetch` (`internal/cmd/sync/fetch.go`, backed by `internal/syncer/fetch.go`) beside `clone`/`pull`/`push`/`status`/`diff` — each its own literal-named FlagSet, per the `flagSetOwners` rule above.

## Invariants

Each cost something real to learn. Do not relax one without understanding why it exists; the
named test is the guard.

1. **Never write a file whose decoded length disagrees with `list_files`' `size`.** A mismatch means a corrupt decode; refuse rather than land a bad file. Caught 2/100 silently corrupted files, and a truncation-notice splice besides. The same check gates a fetch baseline: a sha recorded from a decode whose length disagreed with `size` would, one run later, declare a **different** local file identical — the failure displaced by a run, arriving where nothing is left to catch it. A path failing the check gets no baseline entry rather than a wrong one. `TestFetchWritesNoEntryWhenTheDecodedLengthDisagrees`.
2. **Conflicts key off the bytes, never the etag.** An etag comparison can't see the both-sides-changed case. `TestPlanPullBothSidesChangedIsAConflict`.
3. **An interrupted operation is a failure, not a short success.** A goroutine leaving via `<-ctx.Done()` records nothing; keep the caller's context separate from the derived one so only the parent distinguishes "interrupted" from "gave up", or `--prune` reads a partial tree as server-side deletions.
4. **`--prune` deletes only what we can prove was ours and unmodified.** Untracked → not ours; locally edited → a conflict; `binary: true` → never on disk, so its absence is not a deletion. A path that is not a regular file is not proof of anything (`localFile.Irregular`). And a prune-conflict under `--force` *deletes* — say so, don't print "--force to overwrite".
5. **The ledger is saved whenever bytes moved, error paths included.** A file on disk with no ledger entry becomes a conflict next run, pushing the user to `--force`. Its on-disk shape is a compatibility contract that `load`/`save` can't police (they agree by construction); `ledger_golden_test.go` holds hand-written bytes. A ledger naming files but *no* project is damage, not a state: both bind guards short-circuit on an empty `ProjectID`, so it passes as any project's while its etags stay fully trusted by the prune loop. `LoadState` refuses it and names `pull` as the repair, never `--force`. An empty files map with no project is just an unsynced directory. `ledger_damage_test.go`. The ledger lives at `.dsx/state.json`, not the directory root — `StateDir`/`StatePath` in `state.go`. `State` and `FileState` gained no field and no tag for the move, so `ledger_golden_test.go`'s hand-written bytes pass unedited; that is the proof the schema itself did not change, only its address. `save` still cannot refuse: the checks that can — `checkLedgerHome`'s symlink, non-directory and unwritable refusals — run separately, above the first act (invariant 16), so the `_ = st.save(o.Dir)` sites keep meaning what they meant. There is no reader fallback to a pre-`.dsx/` path and no automatic migration: an earlier, never widely-distributed dsx kept the ledger at `.dsx-state.json` in the root, and `LoadState` does not look for it — see README's upgrade paragraph for the one manual command.
6. **Only read-only tools may be retried on a transport fault.** A `5xx`/connection error can land after the server applied a mutation; `429` is safe (rejected before running). `readOnlyTools` matches `readOnlyHint` in `reference/mcp-tools.json`. `destructiveHint` is **not** a usable retry signal (the server sets it `true` on read-only tools).
7. **Remote paths and their bytes are untrusted input.** `safeJoin` refuses escapes including through symlinks; `checkRemotePath` refuses `.git`, `node_modules`, the ledger. Both compare case-insensitively because APFS folds case. `.dsx` itself is a builtin ignore, spelled bare and slash-free: the builtins loop never strips a trailing slash — only the user-line loop does — so `.dsx/` would compile anchored, demanding a literal trailing slash `match` and `canSkipDir` never supply, and silently guard nothing. Bare, it is unanchored, case-folded, skips the whole subtree through `matchesBuiltinDir`, cannot be re-included by a user `!` rule, and makes `checkRemotePath` refuse a `.dsx` segment at any depth. A file's content can mimic the server's framing, so strips must be anchored. The ledger's own siblings count as its name: `save` writes through `os.CreateTemp(StateDir(dir), stateBaseName+".*")`, `writeAtomic` through `tempPrefix = oldStateFileName+".part-"`, and the fold probe through `os.MkdirTemp`, and the builtin patterns are anchored — an unmatched leftover is an untracked local file the next push uploads, which for the ledger sibling means dsx's project id and full file map landing in the design project. `tempPrefix` is frozen to `oldStateFileName` — the ledger's pre-`.dsx/` name — and not to where the ledger lives now, and that literal can never change: `writeAtomic`'s temps are born out in the working tree, in whatever subdirectory the fetched path lives in, not only at the root, and an already-shipped binary's `builtinIgnores` is compiled in — it can never learn a prefix invented later, so renaming `tempPrefix` would satisfy the new binary and leave an old one pushing a half-written fragment to the server. Both consumers of `builtinIgnores` must read it as globs; `isBuiltinIgnoredName` compared literals and would have silently stopped guarding `checkRemotePath` the moment an entry grew a `*`. Server text dsx *renders* is untrusted too, not only paths and bytes: a `\r` in a project name or a fetched path rewrites what the terminal already showed, and dsx prints warnings there. `fmtutil.Printable` is the one sanitiser, and the fallback that passes an unrecognised reply through needs it as much as the formatted branch — that fallback is the path a hostile reply takes. `temp_sibling_test.go`, `progress_test.go`, `internal/cmd/projects/projects_test.go`, `atomic_test.go`.
8. **The token is read, never written, never printed.** Refreshing it would rotate the refresh token out from under Claude Code. An expired token is reported; the fix is to run any `claude` command. The line is ambient input vs. requested output, not secret vs. not: the OAuth token is ambient — no verb asks for it, and `auth.go` refuses to wrap it even into an error text — whereas a scoped capability a tool *returns* is the output that was asked for, so it prints. `finalize_plan`'s `plan_token` and `render_preview`'s `serve_url` (a `*.claudeusercontent.com` link with a project-scoped token embedded) both do; `files put --plan` documents itself as taking "plan_token from `dsx plan new`", i.e. the user is told to read it off stdout. So `dsx plan new` and `dsx files preview` stdout is credential-bearing and short-lived — print it, don't log or persist it (the server's own `render_preview` description asks the same of `serve_url`). Read instead as a blanket "never print anything token-shaped", this invariant yields a false leak finding against `files preview` — one has been filed and withdrawn already.
9. **`.dsxignore` filters both sides, never one.** A path hidden locally but left in the server listing is indistinguishable from a user deletion, so `push --prune` would delete it. `survey` is the only filter and takes no `*ignoreSet` by design; `loadIgnore`/`filterRemote`/`scanLocal` are unexported so a one-sided filter outside `syncer` won't compile. Wiring is guarded by `prune_ignore_test.go`; the structural half by `TestSyncCallersCannotFilterOneSide`.
10. **`var version` stays in `main.go`, named `version`, threaded to `cli.Main`.** It is `-X main.version`'s target; `-X` aimed at a symbol that no longer exists builds clean and ships `(unknown)`. No test can catch this — CI builds with `-X main.version=v0.0.0-cistamp` and greps. Do not delete that step.
11. **`groups` is the only place a command is declared.** Dispatch, shells and `dsx help` all derive from it, so a missing command is absent code, not a failing test. `TestEveryCommandFormStartsWithItsName` guards `Form` vs `Name`; `TestEveryDeclaredGroupIsRegistered` (parses `.` and `../cmd/*`, resolves the import alias) guards a `Group` var forgotten from `groups`; `TestUsageIsGeneratedByteForByte` holds the hand-written usage golden. Derivation is in `init()`, not var initialisers, to avoid an import cycle.
12. **A report field naming an ACT is assigned when the act completes, never when it is only planned.** `PushReport`/`PullReport` were filled right after planning and only then executed, so every error return between that assignment and the act turned an intention into a claimed outcome: `Deleted` reported a delete the same error text denied, and `PushReport.Bytes` counted a payload never acked. Push's `Written` (appended only after a server etag ack) and pull's `Fetched`/`Bytes` (appended only after `os.WriteFile` returned nil) already had the right shape — copy it, and do not go hunting the `Bytes` defect in `pull.go`, where it never existed. The DryRun branch is the one legitimate place a plan is reported as an outcome; a field naming a DETERMINATION (`Unchanged`, `Conflicts`, `Irregular`, …) may still be filled from the plan. Push half: `TestPushDeletedIsEmptyWhenTheWriteFailedBeforeTheDeletes` (the `Bytes` guard — the delete-call test passes with `Bytes` assigned at plan time), `TestPushDeletedIsEmptyWhenTheDeleteCallFailed`, `TestPushDryRunStillPreviewsTheDeletesAndBytes`. Pull half: `TestPullDeletedNamesOnlyThePathsActuallyRemoved`, `TestPullDeletedIsEmptyWhenTheFetchFailedBeforeThePrune`. The anchor got stricter with invariant 15: `Fetched`/`Bytes` now follow a *returned rename*, not a returned `os.WriteFile`.
13. **The binding is (project, endpoint) and both halves are checked.** `State.Endpoint` had two writers and no reader, so pointing `DSX_ENDPOINT` elsewhere made a foreign listing describe our tree: every tracked path read as server-deleted and `--prune` removed it *unforced*. Worse on the other side — a mutation test showed push reaching `write_files`, i.e. the project's bytes and the Bearer token going to whatever host the variable named. Only scheme and host decide identity: a vendor moving `/v1/design/mcp` to `/v2` must not strand every ledger on disk. The comparison lives in `syncer` beside the project guard, not in `mcp` — the ledger *compares* an endpoint, it never *dials* one. Neither guard is unlocked by `--force`, and neither refusal suggests deleting the ledger: clearing it makes every path untracked and `planPush` then leaves `IfMatch` empty under `--force`, a write with no precondition at all. `endpoint_guard_test.go`.
14. **Presentation may hang off the terminal; nothing semantic ever may.** The transfer counter is the only thing that asks whether stderr is a character device; the answer is read once in `cli` and passed down by value. No mutation, no exit code and no byte of stdout changes with it. A leaf package that read `os.Stderr`'s mode itself would carry a dark branch under every test that swaps the stream for a pipe — hence `DSX_PROGRESS=always`, which is what makes the drawing branch reachable at all. The same rule sorts the rest: a report field is free to gain `incomplete,omitempty` because success bytes do not move, and `tree`/`cat` may read the ledger because they mutate nothing, while `ls` may not (one positional would mean project or path depending on cwd) and `put`/`rm`/`cp` may not (cwd must not choose the target of a destructive act). `tree`/`cat` read it through `syncer.FindRoot`, not `LoadState(".")`, for the reason the sync verbs do: stopping at the cwd hides the binding again one directory down, so `cd components && dsx files tree` refused in a tree where `dsx pull` worked. The writes deliberately do not follow — a ledger the caller never stood in is one step further from their attention than the case this invariant already forbids (`TestNoWriteWalksUpForItsProject`). `put`'s ledger *warning* does follow, because it is a read and because silence from a subdirectory reads as "no ledger is affected" exactly where the trap is easiest to hit; it names the tree it found rather than `./`, which from there holds no ledger at all. `internal/cli/tty_test.go`, `boundproject_test.go`. `fetch` is a mutating verb whose name suggests otherwise — it creates `.dsx/` and writes `baseline.json`, touching nothing else in the tree — so its `Desc` and its docs say so out loud rather than let the verb imply a read.

15. **dsx writes every file the way it writes its own ledger: temp beside the destination, then rename.** `save` had it from the start; `os.WriteFile` opens with `O_TRUNC`, so its destroying step strictly precedes its creating one and a killed pull left a dense prefix of the new bytes and none of the old. The second-order cost was worse than the truncation: the fragment never reaches the ledger (the write precedes `withFile`), so the next run calls it `local differs; --force to overwrite` — dsx wrecks a file, blames its owner, and offers the one destructive flag as the cure. Four details are load-bearing and each has a mutation to prove it. *Not* `os.CreateTemp`: it hardcodes `0600` and a `Chmod` afterwards bypasses umask, so the two possible slips are opposite — narrowing to `0600`, or *widening* to `0644` under `umask 077`; the umask test must assert under `022` as well, because under `077` both spellings agree and prove nothing. The mode is **preserved, never assigned** — `os.WriteFile` applies its perm only on create, so a `chmod +x` on a pulled script survives every pull today and a flat `Chmod(0o644)` would strip it. The temp goes beside the destination, never `os.TempDir()`, or a tree under `/Volumes` gets `EXDEV` from an implementation that passed every test on the author's machine. And a read-only destination is refused before the act: `rename` checks write permission on the *directory*, so `chmod -w` would otherwise stop being a gesture. No `fsync` — the threat model is a killed process, which a returned `rename` fully covers; power loss is a different property and `save` does not pay for it either. Accepted costs, on the happy path and not only after a crash: `rename` swaps the inode, so hard links break and xattrs are destroyed. `atomic_test.go`. The rule extends one level up for `.dsx/` itself: `ensureLedgerHome` creates it with `MkdirAll(StateDir(dir), 0o755)` and never `Chmod`s afterward, for the same reason a written file's mode is preserved rather than assigned — the kernel applies umask at creation regardless of the mode argument, and a corrective `Chmod` would widen to `0755` a directory the owner's `umask 077` deliberately made `0700`, on every save (`TestEnsureLedgerHomeHonoursUmaskAndNeverChmods`, asserted under both `022` and `077` for the same reason the file-mode test is). `checkLedgerHome` `Lstat`s `.dsx` before any of that runs: `MkdirAll` follows a symlinked component silently, in-tree or out, and `safeJoin`'s symlink refusals never see this path, since `.dsx` is not server-derived. `checkLedgerHomeWritable` then probes the directory the way `save` will actually use it — an `os.CreateTemp` that is created and removed — rather than inferring from mode bits, which are wrong under ACLs and for root.
16. **A refusal leaves no trace, and lands before the act it refuses.** Three separate defects turned out to be one rule: `status` and `pull -n` created the directory they were pointed at, so a typo became a real directory and the report described a sync into it (the `status` half is now unconstructible — it takes no directory and makes no call, so `dryrun_nomkdir_test.go` pairs `pull -n` with `push -n` instead; left in, that case would have passed on the takes-no-arguments refusal rather than the one the test is named for); a first pull into a populated directory wrote every non-conflicting path *before* reporting the conflict, leaving a half-foreign tree the caller never agreed to and cannot tell from their own work; and `clone`'s target checks all precede the round trip, because a clone that has already asked the server has spent what it was refusing to spend. The first-contact rule is deliberately narrow — with an empty ledger no path was ever asked for, whereas in an established sync a conflict on one path must *not* stop the others, or conflicts stop being recoverable one file at a time. Do not "fix" the missing-directory case by tolerating it in `syncer`: an empty local scan is exactly what makes `push --prune` read the whole server tree as user deletions, so "not there" must never reach a plan. `dryrun_nomkdir_test.go`, `first_contact_test.go`, `clone_test.go`. `checkLedgerHome` is the same shape again: read-only, safe to call unconditionally including on a dry run, and it runs in `Pull` and `Push` right after the project/endpoint guards and above `WalkTree` and the first-contact gate (`checkPathCollisions`), so a refusal there still leaves no trace — the write half, `ensureLedgerHome`, is reachable only from `save` and `Baseline.save`, both already below their function's act. `refuseMissingDir` now runs inside `resolveSyncTarget`, above the ledger read and for every sync verb rather than only the dry runs — the hoist is what invariant 18 buys, and it is not cosmetic: a path that is not there has no ledger, so the unbound refusal would otherwise tell the caller to `dsx pin` a directory that does not exist, an accurate message displaced by a misleading one. `pin` and `unpin` call it directly, since they resolve no project and nothing else would ever catch the typo.

17. **A fetch baseline is a proof about bytes, and it may only ever turn a conflict into `verified`.** The server never returns a content hash — `list_files` gives path, type, size and etag and nothing else — so answering *are my bytes the server's bytes* costs one download, and the obvious place to keep the answer is `State.Files`. That was tried and measured: with a baseline written there, `push --prune` scheduled every remote path the user did not hold locally for deletion, unforced. The subtler version is worse and looks safer — record the proof as a real ledger entry once a pull has confirmed it — because a file the *user* authored is then `tracked`, so deleting their own copy makes `push --prune` delete the server's, and a teammate deleting the server's makes `pull --prune` delete theirs, both with no `--force`, because `tracked` has quietly stopped meaning "dsx put these bytes here" and started meaning "these bytes match". So the baseline lives in `.dsx/baseline.json`, in a `BaselineEntry` that is field-for-field identical to `FileState` and deliberately not that type — the duplication is the guard, `st.Files = b.Verified` does not compile, and it must never be DRY'd (`TestBaselineEntryIsADistinctType`). It reaches a decision as its own parameter to `planPull`/`planPush`, and `State.Files` is never written from it, so both prune loops — which key off `st.Files` alone — are unreachable by construction rather than by inspection (`TestBaselineNeverBecomesTracked`). `proven` requires all six of: present on disk, not irregular, **not** tracked (a real ledger entry always wins, so invariant 2's both-sides-changed case is untouched), a non-empty baseline etag equal to a non-empty listing etag, and a non-empty baseline sha equal to the local sha — the empty-etag halves are not belt-and-braces, a missing map key yields a zero entry and `b.Etag == remote[p].Etag` alone would let it prove a path the server no longer has. The freshness gate lives *inside* `plan.go`, under the 95% floor: nothing is ever forged into `State.Files`, so there is no forged fall-through arm to gate against, and the whole feature is bounded by one property — `proven` appears in exactly two terminal arms and touches no other slice, so it can only ever move a path out of `Conflicts` and into `Verified` (`TestAProvenByteMatchIsVerifiedNotAConflict`, `TestBaselineOnlyEverMovesAPathFromConflictsToVerified`). A proven path is never promoted into the ledger — it stays untracked and is re-consulted from `baseline.json` on every run, which is the cost of keeping invariant 4's "untracked → not ours" exactly true. Two further predicates share `proven`'s six preconditions and diverge only in how the etag/sha comparison comes out: `diverged` (b.Etag == r.Etag, b.SHA != current sha) is a proven divergence against the CURRENT revision — the last `dsx fetch` checked exactly this listing and found the bytes to differ, so Render/Outcome say so and name `--force`, not `dsx fetch` (`TestADivergedConflictStillExitsNonZero`, `TestOutcomeDivergedOnlyStatesTheDivergence`). `staleProof` (b.Etag != r.Etag, b.SHA == current sha) is the opposite failure of freshness: the baseline proved these exact bytes once, but against a revision the listing no longer shows — every write rotates the etag, content-identical or not, so a same-content resave by anyone lands every unedited path here at once; this is not a rare shape. Both are bounded the same way `proven` is, just one `Unverified` narrower: before either predicate existed, an untracked, present, on-server path that disagreed with the ledger's idea of unchanged fell straight into `Unverified` — `diverged` carves the proven-divergent slice out of that and `staleProof` carves out the proved-but-outdated slice, each appearing in exactly two terminal arms (pull, push) and touching no other slice by the same switch-statement shape that bounds `proven`. `staleProof`'s bound is pinned by its own fuzz test, the `Unverified`→`StaleProof` sibling of `TestBaselineOnlyEverMovesAPathFromConflictsToVerified`: injecting a staleProof-shaped entry may only ever move that exact path out of `Unverified` into `StaleProof`, never into `Verified`, `Diverged`, a tracked `Conflicts`, `Unchanged`, `Fetch`/`Write`, `Irregular`, `Binary`, or either prune slice (`TestStaleProofOnlyMovesAPathFromUnverifiedToStaleProof`). `diverged` has the same bound pinned the same way (`TestDivergedOnlyMovesAPathFromUnverifiedToDiverged`), injecting an etag-equal/sha-unequal entry instead. Its machine-facing half needed one more assertion than it had: `TestOutcomeDivergedOnlyStatesTheDivergence` checked that the hint does not claim "never verified", but not that the generic "local differs"/"server moved ahead" clause stays off a class that already carries its own wording — so dropping `r.Diverged` from `except()` in either `Outcome` survived the suite, gluing two contradictory sentences onto one path. Like a proven match, neither a diverged nor a stale-proof path is ever promoted into the ledger. Two conjuncts in those arms were unguarded until a mutation audit found them, and both mutations had survived the whole suite: the `!force` that makes `--force` fall through to the act instead of leaving the path a conflict (`TestForceFallsThroughTheBaselineConflictArms`, all four arms), and `staleProof`'s empty-etag halves — unlike `proven`, where `b.Etag == r.Etag` makes `b.Etag != ""` and `r.Etag != ""` logically equivalent and no fixture can tell them apart, `b.Etag != r.Etag` makes each independently falsifiable, so each is pinned (`TestEmptyEtagNeverMakesAStaleProof`). The reports' own `omitempty` contract is a third such gap now closed: every conflict-class slice must vanish when empty and appear when filled, which is the exact opposite of `Baseline.Verified`'s contract, and a zero-value golden pins both directions at once (`TestReportOmitemptyContract`, `baseline_golden_test.go`).

18. **Only `clone` and `pin` name a project, and only they and `unpin` take an argument at all; every other sync verb acts on the tree it is standing in.** This landed in two steps and the second one is what makes the first safe. First the project positional went, for the reasons below. Then the directory positional went too, once `syncer.FindRoot` (walk up to `.dsx/state.json`, the way git finds `.git`) covered "I am inside the tree" and the global `dsx -C <dir>` covered "I am outside it" — between them nothing was left for an argument to say. Dropping it before those two existed would have been a strict regression, and dropping the project first was not: `clone` and `pin` already covered that case. The order is the rule. What the second step also buys: `refuseMissingDir` is no longer reachable from `resolveSyncTarget` (the working directory exists by standing in it) and its only callers are now `pin` and `unpin`; and a positional is always a mistake, so the refusal names the replacement — `dsx -C <dir> <verb>` for a path, `pin`/`clone` for an id. That id arm has caught the same defect twice, both times an advice string that would create a directory named after a project id (`uuidasdir_test.go`). `-C` is parsed by `splitGlobalFlags` before the command name is read and applied with `os.Chdir`, because every path dsx resolves already answers to the working directory; it is documented in usage's GLOBAL block, which `footerFlagScopes` skips deliberately — a global has no per-command declaration to match, so `TestTheGlobalBlockDocumentsExactlyTheRealGlobals` ties that block to the parser instead of to prose. The original reasons for dropping the project follow. The two-positional form made `<project> <dir>` and a lone `<dir>` mean different things at the same arity boundary, and paid for it with `looksLikeProjectID` and a refusal that had to guess which mistake the caller made. It bought nothing `clone` and `pin` did not already cover — `clone` for an empty directory, `pin` for a populated one — and it cost the accuracy of every refusal downstream. Three consequences are load-bearing, not incidental. The mismatch arm of the project guard in `Pull`/`Push`/`Fetch`/`Diff` (`st.ProjectID != "" && st.ProjectID != o.ProjectID`) is now **unconstructible from the CLI**: a project reaches those functions only through the ledger it is compared against. The guard stays — it still answers for a library caller and its endpoint half is still reachable through `DSX_ENDPOINT` — but its test belongs at the `syncer` layer, which is where `TestFetchRefusesAForeignProjectBeforeTheRoundTrip` was moved rather than deleted. `pull` no longer creates its target: a directory `pull` could create is a directory `pull` cannot resolve a project for, so `cmdSync`'s `MkdirAll` is gone and `clone` is the only verb that starts a directory (`TestNeitherPullNorPushCreatesTheTargetDirectory`). And every refusal that used to advise re-running the same verb with a project in front now names `pin` or `clone`, because the form it advised no longer parses — `TestTheNoLedgerRefusalNamesOnlyFormsThatParse` asserts both halves for all five verbs, and `refuseMissingDir`'s own text names `clone`, not `pull`. The premise the whole design rests on is that none of the five writes the binding it reads; `TestNoSyncVerbWritesTheBindingItReads` and `TestFetchWritesUnderDsxButNotTheLedger` hold it, the second because `fetch` does write under `.dsx/` and is the easy one to disbelieve. `unpin` exists because `pin` refuses to rebind and a mandatory gate with no exit turns a typo into a ledger repairable only by hand; it releases only a binding with an empty `Files`, which is invariant 13's own warning read from the other side, and it is the one sync verb declared `NeedNothing`.


19. **`status` answers from disk alone; `fetch` is what makes that possible, and a missing snapshot is refused rather than shaded.** git's three network verbs are asymmetric and dsx's were not: `git fetch` writes only bookkeeping, `git pull` fetches by definition, `git push` never fetches and leans on a server-side precondition, and `git status` makes no network call at all — verified by running each rather than read off the docs. dsx matched the first three and inverted the fourth: `status` was `pull -n` plus `push -n`, so it always spent a `list_files`, and — worse — reported every adopted file as a conflict whose only named cure was `--force`, the one destructive flag, which is invariant 5's warning arriving from the other side. The fix is in two steps and the order is the rule, as in invariant 18: `fetch` first records the whole ignore-filtered listing in `.dsx/baseline.json`, and only then may `status` stop asking. Reversed, `status` would have nothing to answer from. Three things are load-bearing. The snapshot is `SnapshotEntry`, deliberately not `RemoteEntry`, for the reason `BaselineEntry` is not `FileState` and with higher stakes: a snapshot has the shape of the live listing `planPull`/`planPush` take, so `map[string]RemoteEntry` would let a *stale* one compile into a plan and `--prune` would read every path the server has since gained as a user deletion (`TestSnapshotEntryIsADistinctType`). It is recorded already filtered, because no reader can filter it — `filterRemote` takes `RemoteEntry`, and `TestSyncCallersCannotFilterOneSide` forbids anyone but `survey` from touching the ignore machinery — so an ignored path recorded once is named forever (`TestTheSnapshotIsRecordedAlreadyFiltered`). And `nil` is not an empty map: the tag carries no `omitempty` and `loadBaseline`'s nil-fixup stays `Verified`'s alone, or every baseline written before this field asserts an empty server. That last one nearly shipped as a test that was green for the wrong reason — the refusal fired through `bound()` because no baseline existed at all, so a mutation removing the `nil` check survived; `TestStatusRefusesABaselineWrittenBeforeSnapshotsExisted` writes the legacy bytes by hand and is what actually holds it. `status` is the second `NeedNothing` sync verb after `unpin` and for a sharper reason — it makes no call, so a credential is something it has no use for — which is why `TestUnpinIsTheOnlySyncVerbThatNeedsNoCredential` became `TestOnlyTheOfflineSyncVerbsNeedNoCredential`: the list is the claim, and adding a name to it asserts that verb reaches no network. `--prune`, `--force`, `-n` and `-j` left `status` with the round trip they configured. `pull -n`/`push -n` are the live question and keep every one of them.

20. **`push --force-with-lease` overwrites only what the last fetch still accounts for; blind `--force` stays exactly as dangerous as it was.** Running real git confirmed dsx's `--force` *is* git's: the branch falls past setting `IfMatch`, so the write carries no precondition at all, and `PushReport` holds no field naming a third party's silently destroyed change. git's safe middle is `--force-with-lease`, and dsx already had the value for one sitting in `.dsx/baseline.json`. The lease reads the **snapshot**, never this run's listing — a live listing answers "what is there now", which is blind force with a smaller window, and the case git actually catches is "you fetched but never looked". `force bool` became `pushForce` with three values because there are three answers; two bools would leave the impossible fourth state (blind and leased at once) to be excluded by hand at every reader, and the seven `!force` arms became `mode == forceNone`. A lease holds when the server still shows the etag the snapshot recorded, or when the name was free then and is free now (`IfMatch: "0"`); otherwise the path goes to `LeaseBroken` and is not written. That arm sits below `proven` — a path already equal to the server costs no refusal — and above every remaining one, because once the server moved after our fetch nothing else about the path matters. The refusal names `dsx fetch` and never `--force`: the lease was broken by someone else's write, and answering that with a blind overwrite is the destruction the flag was asked for to prevent. Two defects were found by mutation rather than by design. Dropping the non-empty etag halves lets `"" == ""` hold a lease and send `IfMatch: ""` — a blind force wearing the lease's name, the one outcome the flag must make impossible (`TestAnEmptyEtagNeverHoldsALease`, all three shapes). And initialising `snapshot` to an empty map instead of leaving it nil made the pre-round-trip guard unfireable on an unbound baseline, so a lease with nothing behind it held for every path the server lacked; nil is what makes "no fetch ran here" and "that baseline is another binding's" arrive as the same state. `--force` and `--force-with-lease` are refused together rather than ranked, because a caller who wrote both asked for two different writes and keeping either silently is a guess about which. **The delete lane needed the lease too, and shipped without it.** The prune loop gated its only staleness check on `mode == forceNone`, so `forceLease` fell straight through to `d.Delete`: `leaseHeld` is computed in the write loop and was never read there, and `push --force-with-lease --prune` removed whatever a teammate had written after the fetch — this invariant's opening sentence as a promise with no mechanism under it. The one remaining backstop was `deletePaths` sending `if_match: prev.Etag` and the server refusing, which rests on behaviour PROTOCOL.md pins live for `write_files` only. The arm is asked **first**, above the `forceNone` staleness check, because under `forceLease` that check never fires; it reads the snapshot against the listing exactly as the write lane does, and both etags must be non-empty for the same reason (`"" == ""` is not a lease). A refused delete gets its own slice, `PruneLeaseBroken`, rather than joining `LeaseBroken` or `PruneConflicts`: the first says "not written", true of a refused delete only in the uninformative sense, and the second offers `--force` as the cure, which for a lease someone else broke is the destruction the flag was asked for to prevent. `TestALeasedPruneRefusesAPathTheServerMovedPast` pairs the refusal with two controls — a held lease must still delete, or `--prune` is merely broken, and blind `--force` must still delete, because this invariant says it stays exactly as dangerous. The defect was invisible from below: every lease test drove `planPush` directly and none passed `prune: true`, so `rep.LeaseBroken = nil` and `rep.PruneLeaseBroken = nil` both survived the whole suite — dropping either sends the path into `Outcome`'s `plain` bucket, which advises `--force` by name. `TestABrokenLeaseReachesTheReportAndTheHint` asserts the wording, not the exit code, because the code is 3 either way.

21. **An exit code states something about the TREE, not about what this invocation managed to do — so a dry run carries the same code as the run it previews.** `-n` used to suppress it: `pull -n` on a conflicted tree exited 0 while `pull` on the same tree exited 3, so an agent that ran the preview to decide whether to proceed was told "clear" and met 3 on the very next command. The deciding evidence is dsx's own, not git's: under `-q` a real pull prints *nothing* and the exit code alone carries the conflict (`TestSyncQuietPrintsNothingButStillReportsTheConflict`), which is only coherent if the code answers "what is the state of the world" rather than "did this command finish what it attempted". README had argued the opposite in prose — "it was asked to move nothing, so refusing to move something is the answer it wanted" — and that argument convicts `-q` too, which deliberately does not follow it. A dry run reaches the same `planPull`, fills the same `Conflicts`, and was the only place in dsx that computed the fact and discarded it. Corroborating but not deciding: `git push --dry-run` exits 1 on a non-fast-forward exactly as a real push does, while `git status`/`git diff` exit 0 and need an opt-in `--exit-code`; measured, not recalled. The `dryRun bool` parameter did not survive the change — with the arm gone nothing read it, and a parameter accepted and ignored is a standing invitation to re-add the suppression, so the signature is `Outcome()` and `clone`'s literal `false` disappeared with it. `ConflictOutcome` was deleted rather than amended: no production path ever called it (the sorting and hint-carriage it appeared to guard were pinned on a copy of logic the binary does not run), and leaving it would keep a function implementing the rule just deleted. **`status` and `diff` must not follow.** That is the consistency the next hand will reach for and it is wrong here for a reason specific to dsx: invariant 19 makes `status` answer from a `.dsx/baseline.json` snapshot of arbitrary age, so a 3 from it would be a verdict about a server this run never contacted — the exact failure invariant 19 removed. Their exiting 0 is what leaves an agent a command it can run to *look* without receiving a verdict. `diff` keeps its one unrelated conflict exit, `checkOutCollisions` on `--out`, which refuses to write rather than reporting divergence. Also untouched: `PullOpts.DryRun`/`PushOpts.DryRun`, the field that actually gates the write phase, and invariant 12's DryRun branch, where filling report fields from the plan stays correct. `TestADryRunCarriesTheSameExitCodeAsTheRunItPreviews` holds it as three rows — real-run-conflicts and clean-dry-run are the paired controls, so the middle row can neither pass on a fixture that stopped conflicting nor on an unconditional refusal.

22. **`Command.Name` is the full address, and it is the address because a refusal prints it.** Everything except the sync verbs and the two escape/diagnostic groups now addresses as `dsx <noun> <verb>`; the flat spellings were removed outright, with no alias and no deprecation window. The mechanism looks like it could keep the bare verb in `Name` and prepend the noun at dispatch — that was designed and rejected on one measurement. `ParseArgs` returns `Msg: "dsx " + fs.Name()` and `Dispatch` passes `c.Name` into `EmitFlagged`, so a bare `Name` makes the commonest possible mistake — a typo in a flag — answer `dsx cat: flag provided but not defined`, naming a form the same commit deleted. That is invariant 18 failing not in a corner but on every migrated verb, which is why the two-token `Name` is load-bearing and not a spelling choice. `commandIndex` stays a flat map keyed by that address; `nounIndex` answers the one question dispatch asks of the first token, and `topNames` (flat commands plus nouns, no verbs) is what a shell offers in first position. The objection to a composite `Name` was real — `commandFlags` matches footer scopes through `commands[c.Name]` — and it is answered by writing the scopes in two tokens (`— files put, files cp, project support-js`), which both readers survive unedited because `footerScopes` and `footerFlagScopes` split on the comma and `TrimSpace`. Four details cost something. Second-level derivation must happen in `init()` for a *new* reason on top of invariant 11's: `completionScript` reads the registry, `diagGroup` holds `cmdCompletion`, `groups` holds `diagGroup`, and a var initialiser closes a cycle the compiler refuses by name. A dash where the verb goes is a help request, not a verb, or `dsx files --json` refuses a flag by calling it an unknown verb — `TestNoVerbIsSpelledLikeAFlag` stops that branch swallowing a real one. **That guard reads the registry, not the invocation, and the invocation is where the branch actually swallowed one.** It asserts no *declared* verb is spelled like a flag; it cannot see a real verb standing one token behind a flag, and `printNounHelp` reads only `args[0]`. So `dsx member --json rm p uuid` printed the verb list and exited 0 — nobody removed, stderr empty, no `error` key in the JSON — which is the one shape an agent cannot detect, since dsx's own contract tells it to branch on the exit code and on `dsxerr`'s token. The root level already refuses the same mistake (`dsx --json pull` is a usage error), so the noun branch was strictly the weaker of the two levels, and the migration is what introduced the asymmetry: before it there was no second level. `misplacedVerb` closes it by scanning for a verb **this noun declares** — not any non-flag token, or a flag's value and a foreign noun's verb would both be read as one (`TestOnlyThisNounsOwnVerbsCountAsMisplaced`) — and `reorderVerbFirst` rebuilds the caller's own line with the verb in front rather than printing a bare form, which invariant 18 permits precisely because `ParseArgs` takes flags before, between and after positionals once a verb's FlagSet is reached, so every argument they typed survives the rewrite (`TestTheMisplacedFlagRefusalRebuildsTheWholeLine`). The dash branch keeps answering the question it was written for: a flag with no verb behind it is still a question about the noun. A bare noun exits 0 listing its verbs, matching bare `dsx` one level up. And the noun help computes its own description column, because every form there carries the noun too and one outlier (`conv put`, a hundred characters) would otherwise drag every sibling's description off the screen. Three mutations survived the first round of tests and each named a real gap: a section heading printed per verb rather than per change of section (the fixture held one verb per section, so no repeat could show); the noun dropped from the address, where `dsx conv put` silently reached the *file-writing* `put` and no test ran a real verb through `run()` at all (`TestEveryNounVerbIsReachedThroughDispatch`); and a verb moved between READ and WRITE, which nothing saw because `dsx files -h` was rendered by no golden (`wantFilesHelp`, hand-written for the reason `wantUsage` is). What the migration also exposed is older than itself: invariant 18 was enforced by hand in the sync refusals, so four printed strings elsewhere — `clone`'s advice, `conflictHint`, `put`/`cp`'s `--plan` help, `GrantError` — named forms that no longer parsed. `TestEveryDsxInvocationInSourceNamesARealCommand` now reads that invariant as data across every production `.go`, narrowed twice by measurement: in comments only a backticked span counts (*"every path dsx resolves"* is prose), in string literals only command position (`# dsx bash completion` is a script header). A refusal may also *build* a form at runtime, which that guard cannot see, and two now do: `didYouMean` turns an unknown first token into the addresses it could have meant, and `reorderVerbFirst` rebuilds a misplaced-flag line. The unknown-first-token refusal was generic for every removed flat spelling, which was never a decision about those tokens — the specific refusal already existed one token along, since a dead form whose first word is still a noun gets `unknown <noun> verb`, so the generic message was only where the rest fell through. Two shapes are worth suggesting and nothing else is: a bare verb, which is how every removed spelling was written, and a pluralised noun, because the registry is singular there only to match the server's own tool names. A suggestion invented for every typo is worth nothing, so a token resembling neither still gets the old message (`TestATokenLikeNothingElseGetsNoSuggestion`). `TestEverySuggestedFormParses` reads invariant 18 as data one step tighter than the source guard: it runs every dead spelling through `run()` and requires every backticked form the refusal emits to resolve in the registry — its `checked` floor is load-bearing, since dropping the backticks makes the walk find nothing and pass.

23. **`Binary: true` means "dsx did not put these bytes here", and only a path dsx WROTE may clear it.** Not "the content is binary", and specifically **not** "there is no sha": a forced push records the bytes it SENT beside the marker, which is why `TestForcedPushOfABinaryEntryDoesNotArmAPlainPullPrune` exists, and gating the binary arms on `prev.SHA == ""` instead of on the marker was tried first and turned five of those guards off at once. So `pull --binary` clears the marker rather than adding a field — but only where it wrote the file. **An adopted path keeps it**, and that asymmetry is invariant 17's argument arriving through a new door: both prune loops read `Binary: true` as "not ours", and an adopted file is the user's own, matching by coincidence of content, so clearing it would make deleting their copy delete the server's under a plain `push --prune`, and a teammate's deletion delete theirs under a plain `pull --prune` — both unforced, the failure invariant 17 names verbatim. It was written the other way first and a review reproduced both halves. The sha rides beside the marker either way, and *that* is what stops push calling an adopted path a binary conflict, since `BinaryConflicts` asks `prev.SHA == "" || remoteMoved`. Nothing else in the ledger's schema moved, so `ledger_golden_test.go` passes unedited. Four consequences are load-bearing. **The plan cannot decide a binary**: `read_file`'s refusal is what discovers an untracked one and it arrives after planning, so `planPull` routes only the *tracked* ones (`binaryLane && tracked && prev.Binary`, above the skip arm and above every conflict arm — a tracked binary's sha is absent or a record of bytes dsx sent, so `localDirty` says nothing true about it either way and the generic arms would call every one a conflict), and what the local copy really is gets decided in `pull.go`, on the bytes. **The compensating check keys off the ROUTE, not off the download.** That arm jumps over every conflict arm, so `d.BinaryFetch` names the paths it routed and `pull.go` consults that set. Keyed on the binary refusal instead — which is how it was written — a path whose server copy has since become valid UTF-8 takes the same arm, reads back through `read_file` with the check switched off, and overwrites a modified local file with no `--force`, no conflict and exit 0. `TestABinaryThatBecameTextStillCannotOverwriteAModifiedLocalFile`. **An identical local copy is adopted, not rewritten**: a rename swaps the inode, so writing bytes that already match pays invariant 15's accepted cost — broken hard links, destroyed xattrs — for nothing. `Adopted` is the one report field whose act is the ledger entry and nothing else, so it is assigned only once `st.save` has returned nil; the behavioural test for that is unreachable (`checkLedgerHome` probes writability with the same `os.CreateTemp` `save` will use), so `adoptedafterthesave_test.go` pins where the assignment sits and says out loud that this is all it pins. A differing copy is `BinaryDiverged`, the only conflict class proven on the content itself, so its wording names `--force` and never `dsx fetch`, which cannot record a baseline for a tracked path. **And the lane is a live pointer**: `serve_url` serves whatever a path holds now — measured, a URL minted before two writes returned the second one's bytes — and its `ETag` is in a namespace `list_files`' cannot be compared with, so nothing in the download ties the bytes to the revision the run planned against. One extra whole-tree `list_files` after the downloads does. It is deliberately **not** gated on `len(errs) == 0`: another path failing says nothing about these, and skipping their commit leaves `rep.Fetched` calling a path fetched while the ledger still carries the pre-run marker for it. When the listing cannot be had at all — it failed, or the caller interrupted — every downloaded path is named in `Raced` rather than left to the run's error, which says nothing about *which* paths landed unattributed. A raced path keeps its bytes on disk, gets **no** ledger entry, and joins `Conflicts`: it is not a choice between two versions, but neither is `PruneBinary`, and under `-q` the exit code is the only channel that can say the run did not do what `--binary` asked. Its wording names the retry and never `--force`. A preview-lane failure is a failure, not a quieter skip. **`clone` runs the lane unasked and `pull` needs `--binary`**, which is not an inconsistency: the two costs that keep it a flag are an established tree whose behaviour would change under the caller on an upgrade, and a ledger full of `Binary: true` entries that a plain `pull` would start rewriting — an empty directory has neither, and a clone that omits files is not a clone. The escape hatch needs no flag of its own and is pinned by `TestPinThenPlainPullIsTheTextOnlyPath`: `dsx pin`, then a plain `dsx pull`. **`fetch` runs the lane unconditionally, like `clone` and unlike `pull`.** Neither cost that keeps it a flag in `pull` applies: `fetch` writes nothing into the tree, and its target set is the untracked paths alone — the exact set no ledger entry can ever speak for, which is what left an asset stuck in `status`' untracked-differs with no command able to clear it. It does cost bytes, which is what its report has always counted. Two divergences from `pull`'s lane are deliberate. A preview failure there is fatal (`--binary` names those bytes); here it is a reported `Skipped` (nobody named anything, and one unserveable asset must not discard the proof gathered for every other path). And a raced entry there needs its own slice because bytes were left on disk; here dropping the entry is the whole remedy, so it joins `Skipped` — whose rendered line now NAMES the paths, since a bare count leaves the reader unable to tell which path `status` will keep calling untracked-differs. `binary_preview_lane_test.go`; sixteen mutations, each pinned.

## Testing

```bash
go test -race ./...
go vet ./... && go vet -tags=live ./... && gofmt -l .
go run honnef.co/go/tools/cmd/staticcheck@latest ./...
```

- Unit tests cover the pure logic — `plan.go`, `envelope.go`, `state.go`, `ignore.go`, `dsxerr.go`, `mcp.go` parsing. CI enforces 80% overall, 95% on `plan.go` and `envelope.go`. The floor matches by filename substring and is gameable by moving a function out of a held file; don't relocate past the ratchet.
- **`fake_test.go` tests dsx's own handling, never protocol facts** — a mock only repeats what we already believe. Three protocol facts were guessed wrong first (`write_files` returns a map; `needs_project_grant` is HTTP 403; binary detection is by content), and a green mock would have hidden all three.
- **Protocol claims are verified live** (`live_test.go`, `-tags=live`); every claim in PROTOCOL.md has a test there. If one fails, PROTOCOL.md is wrong.
- **Write a defect's test red first and watch it fail.** Better, prove it earns its place: break the line it covers, watch it go red, restore.

### Live testing discipline

Live tests touch real projects and there is **no `delete_project` tool** — the suite must never create one (`TestLiveRefusesToCreateProjects` enforces it).

- write only to `.dsx-selftest*` paths; `liveScratch` registers and verifies removal

## Known unknowns

Untested — do not present as fact.

- The plaintext credential lane has never read a real `.credentials.json` (no Linux machine). Largest remaining gap.
- The write allowlist was probed with ~20 extensions; not exhaustive.
- `put_conversation`, member/sharing tools are wired but only smoke-tested. `render_preview` no longer belongs on this list for the half dsx depends on — see the preview lane in PROTOCOL.md — but its `validators` argument is still declared and still ignored.
- Of the preview lane, only the two facts dsx rests on are pinned live (the bytes, at two sizes, and the project scope of the token). Measured once by hand and NOT re-asserted by any test: that `expires_at` is honoured to the second and what arrives after it; the `.html` preview harness and its size; the absence of `Range`; that the `ETag` is revision-derived; the User-Agent behaviour; and that repeating `render_preview` for one path returns the same URL. dsx does not depend on any of them, which is why they are not paid for on every live run.
- The preview lane has never been run against a project with many binaries at once, nor against one large enough for the concurrency limiter to matter. The real design project's six files, 660 KB total, is the largest measured.
- `get_conversation`'s framing used to sit here as a known unknown phrased as "one of these two beliefs is false"; it was measured on 2026-07-23 and **both** were — see PROTOCOL.md's `get_conversation`. It is wrapped, so "conv prints raw text" was wrong; the wrapper is its own tag carrying only `project_id`, so "wraps like `read_file`" was wrong too, and `ParseEnvelope` refuses it on the missing etag. What remains unmeasured is narrower and is recorded there: whether a project with several chats, or with closed ones, spells the notice's `available:` list differently. A dichotomy is not a measurement — both horns can be false at once, and phrasing an unknown as one hid this shape for as long as the sentence stood.
- That an identical-content re-put rotates the etag was measured once, on one plain-text path in the sandbox project. Binary content, an empty file, two writes closer together than the timestamp's microsecond resolution, and any other project are all unprobed. The mechanism argues the rule is general — the etag decodes to a write timestamp, and a timestamp cannot be a function of content — but only the one case was seen. dsx would not be wrong if the rule had exceptions, only slower: an etag it cannot match drops a path out of `proven` into `stale proof`, which costs one `dsx fetch`, never a wrong answer.
- `finalize_plan` token expiry mid-push (~15 min) has not been hit.
- Whether the server rotates refresh tokens (the reason `auth.go` refuses to refresh) is assumed.

## Conventions

- Go stdlib only, no dependencies — a hard constraint that keeps the binary a single trustworthy artifact. `staticcheck`/`goreleaser` run in CI without entering `go.mod`.
- Terse output by default; `--json` for machines; never print file contents unless asked. Output width is a token budget — which is why the indented fallback is on the human path only: `cmd.PrintReply` hands `--json` the server's bytes untouched, and a `Human` renderer may never reach that path (`TestPrintReplyLeavesJSONToTheMachine`). The one exception is bounded and is not a loophole: where the server's reply **is not a JSON document at all**, "untouched" was never on offer — `--json` was already emitting dsx's own `{"text":…}` wrapper, so the choice is between two dsx shapes and the unusable one was winning. Such a command may declare a `Machine` renderer beside its `Human` one and reach the JSON path deliberately, through `EmitShaped`/`PrintReplyShaped`; it must emit valid JSON or refuse. `get_conversation` is the only one today (`reply.ConversationJSON`), and the test that guards the rule is written about the *human* half specifically so the exception does not silently widen. Do not reach for `Machine` because a server shape is merely awkward — the bar is that it is not JSON. Every renderer lives in `internal/reply` and **may refuse**; a reply that is not the shape that was measured falls through to itself rather than to a table of blanks. Adding a renderer therefore means measuring the reply against the real endpoint first, writing it into PROTOCOL.md, and pinning it with a live test that calls the same decoder — no tool on this server declares an `outputSchema`, so there is nothing else to read.
- Errors say what to do next and carry an `errKind` an agent branches on. Reword the message, never the token.
- **Cite no count that churns.** Test totals, tool counts, line counts move on the next commit and rot into a quiet lie — let the tool that owns the number report it (`dsx help` lists the tools, `go test ./...` runs the suite). A number that pins a *measured* fact — a file size, `2 of 100`, the 256 KiB cap, a coverage floor — is evidence, not a count; it stays.
- **A command's `Form` carries its positionals and its command-unique flags; a flag several commands share is documented once in `usageFooter`, under a scope naming them.** `--json` set that precedent. Widening a Form is not free — `put`, `cp` and `support-js` repeat their Form text in `Need1`/`Need2` literals printed on every malformed invocation, the agent hot path. `TestEveryDeclaredFlagIsDocumented` walks the real `flags.String/Bool/Int` declarations and accepts either home, so a flag can be discoverable without being spelled three times. Accepting *either* home is what lets both homes fill up, and `-j` did: five Forms spelled it while the footer scoped it, and the scope named `tree` — which spells it nowhere — alongside two commands it omitted entirely. `-j` now lives in the footer alone, `tree`'s shape generalised rather than excepted. Two mechanical rules fell out and both are load-bearing. The default is `cmd.DefaultConcurrency`, one constant instead of six literals that merely agreed, and `TestTheFooterQuotesTheRealConcurrencyDefault` ties the footer's `(default 8)` prose to it — that line is a copy no compiler checks, and it fails silently in the direction that matters, still promising the old number after the constant moves. But the flag is **not** wrapped in a `cmd.ConcurrencyFlag` helper the way `--json` is wrapped in `cmd.JSONFlag`, and the asymmetry is deliberate: the guard finds a declaration by matching a selector literally named `String`/`Bool`/`Int`, so a wrapper hides every call from it, and unlike `--json` — whose scope is the unchecked `every command` bypass — `-j`'s scope names its commands, so the backward half would then report all six as documented-but-undeclared. Swapping only the default argument keeps the declaration visible, because the guard reads `call.Args[0]` and nothing else. `--json` earns its helper for the opposite reason: it is on every command, so the only thing a per-command declaration can add is a *different* third argument, and it did — four commands said `JSON output` where the rest said `machine-readable output`, and that argument is what `dsx <cmd> -h` prints. `TestJSONIsDeclaredOnlyThroughTheHelper` forbids the hand-rolled form; it asserts an absence, so it opens by proving the walk still finds `--prune`, which no helper wraps and which two commands will keep declaring by hand.
